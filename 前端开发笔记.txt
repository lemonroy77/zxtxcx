      绿易融线上服务平台 - 转型通小程序 前端开发笔记

【一、项目概述】

项目名称：绿易融线上服务平台 - 转型通小程序
技术栈：uni-app (Vue 2 语法) → 编译为微信小程序
开发工具：HBuilderX
运行方式：HBuilderX → 运行 → 运行到小程序模拟器 → 微信开发者工具

项目定位：
    为银行和企业提供"转型金融"服务的小程序前端。
    企业通过小程序填写信息、提交碳排放数据，系统自动评分，
    最终生成转型认定报告等PDF文件，辅助银行决策转型融资。

当前状态：
    纯前端项目，所有数据均为模拟(Mock)数据。
    后端接口尚未对接，登录/提交/报告下载均为前端模拟。
    对接后端后，只需修改 request.js 中的 BASE_URL 和各页面的接口调用。

【三、路由与导航 (pages.json)】

【四、核心页面详解】

━━━ 4.1 首页 (index.vue) ━━━

功能：
    - 自定义导航栏：Logo (GG图标) + "绿易融" 标题 + 搜索栏
    - Banner轮播：3张绿色渐变背景轮播图
    - 功能导航：3个入口 (转型通/绿融资/找政策)
    - 待办事项：模拟3条审批待办
    - 资讯动态：模拟2条新闻

关键逻辑：
    - 只有"转型通"有实际跳转路径 (/pages/zhuanxing/zhuanxing)
    - "绿融资"和"找政策"点击提示"功能开发中"
    - 搜索栏点击提示"搜索功能开发中"
    - statusBarHeight 通过 uni.getSystemInfoSync() 获取，适配不同机型

数据来源：全部写死在 data() 中


━━━ 4.2 登录页 (login.vue) ━━━

功能：
    - Logo + 应用名 + 标语
    - 账号/密码输入框（密码可切换显示/隐藏）
    - 用户协议勾选
    - 登录按钮
    - 跳转注册

关键逻辑：
    - 表单校验：账号不能空、密码不能空、必须同意协议
    - 模拟登录：不调接口，直接生成 mock_token_时间戳 作为 Token
    - 登录成功后：
        auth.setToken(mockToken)     → 存到 Storage
        auth.setUserInfo(mockUser)   → 存到 Storage
    - 1.5秒后 uni.switchTab 跳转到首页

对接后端时改动点：
    把模拟登录替换为：
    request.post('/api/login', { username, password })
    → 拿到后端返回的 token → auth.setToken(token)


━━━ 4.3 我的页面 (mine.vue) ━━━

功能：
    - 头部：头像 + 用户名/手机号（未登录显示"登录/注册"）
    - 审核状态卡片：根据 auditStatus 显示不同状态图标和文字
    - PDF报告列表：审核通过后展示4份PDF报告下载链接
    - 功能菜单：企业信息录入、信息修改
    - 设置菜单：账号设置、关于我们
    - 退出登录按钮

关键逻辑：
    - onShow() 每次显示时检查登录状态 (auth.isLoggedIn())
    - 未登录点击任何功能都跳转登录页
    - auditStatus 目前写死为 "passed"（模拟已通过）
    - 报告下载：如果 url 不为空就调 uni.downloadFile，否则提示"后台生成"
    - 手机号脱敏显示：138****5678

审核状态 4 种：
    pending    → ⏳ 待审核
    reviewing  → 🔍 审核中
    passed     → ✅ 审核通过（显示PDF报告）
    rejected   → ❌ 审核未通过

对接后端时改动点：
    1. onShow() 中请求用户信息接口获取真实审核状态
    2. 报告列表从后端接口获取（含真实下载URL）
    3. 退出登录时可调后端退出接口


━━━ 4.4 转型通页面 (zhuanxing.vue) ━━━

功能：
    - 头部绿色介绍卡片
    - 8步认定流程列表（可点击跳转）
    - 统计看板：已认定/审核中/待填写/草稿 4个数字
    - 快捷操作：开始认定/继续填写/查看报告/历史记录

关键逻辑：
    - 8步流程全部跳转到 create-body 页面
    - 统计数字目前写死
    - "开始认定" → 跳转企业信息录入
    - 其他快捷操作提示"暂无"

8步认定流程：
    1. 基本要求判断
    2. 碳排放与碳强度计算
    3. 第一次评分计算
    4. 勾选行业目录
    5. 承诺
    6. 第二次评分计算
    7. 材料撰写

━━━ 4.5 企业信息录入 (create-body.vue) ★核心页面★ ━━━

这是整个小程序最核心、最复杂的页面，实现了6步表单。

【Step 0：基本信息】
    填写项：
    - 企业名称 (必填)
    - 统一社会信用代码 (必填，18位)
    - 所属行业 (必填，弹窗选择，12个行业)
    - 法定代表人 (选填)
    - 联系电话 (选填)
    - 6条合规要求勾选 (6.1条款)

    校验规则：
    - 企业名称不能为空
    - 信用代码需≥15位
    - 行业必须选择

【Step 1：能耗数据】
    填写项：
    - 电力与热力：用电量(千瓦时)、用热量(GJ)
    - 燃料燃烧：原煤、焦炭、原油、天然气、液化石油气、汽油、柴油
    - 营业收入(万元)
    - 每项都分"上年"和"本年"两栏

【Step 2：碳排放计算 & 评分】
    自动计算（computed属性，实时响应）：
    - 碳排放总量 = Σ(能耗量 × 排放因子)
    - 碳排放强度 = 碳排放总量 / 营业收入
    - 非化石能源占比 = 电力中非化石占比 × 标准煤系数

    排放因子（EMISSION_FACTORS 常量）：
    - electricity: 0.5810 kgCO2/kWh
    - coal: 1.9003 kgCO2/kg
    - natural_gas: 2.1622 kgCO2/m³
    - diesel: 3.0959 kgCO2/kg
    - 等等...

    第一次评分规则：
    碳排放总量(满分30)：下降≥10% → 30分，下降≥5% → 24分，下降>0 → 15分
    碳排放强度(满分30)：同上规则
    非化石能源占比(满分10)：>25% → 10分，≥20% → 5分
    客观指标合计 = 总量分 + 强度分 + 非化石分 (满分70)
    门槛：客观指标合计 ≥ 48分 才算通过

    未达48分会弹窗提示，用户可选择继续或返回修改

【Step 3：行业目录勾选】
    12大行业目录(可多选)：
    - 钢铁、煤电、建材、农业、化工、石化
    - 冶金(铜)、冶金(铝)、纺织、水上运输、陶瓷

【Step 4：承诺】
    勾选项：
    - 承诺碳排放总量下降
    - 承诺碳排放强度下降
    填写项：
    - 总量目标下降比例(%)
    - 强度目标下降比例(%)
    数据授权：
    - 同意普惠征信使用数据

【Step 5：综合评分 & 提交】
    综合评分 = 客观指标(70) + 转型计划(10) + 融资计划(10) + 治理计划(10)
    (转型/融资/治理计划分数目前模拟为各8分)

    等级划分：
    ≥90 → 领先
    ≥70 → 良好
    ≥50 → 一般
    <50 → 较差

    待生成材料列表：
    - 转型认定报告
    - 融资主体转型规划书
    - 企业环境信息披露报告
    - 碳核算报告

    提交：模拟1.5秒加载 → 提示成功 → 返回上一页

    提交前校验：必须同意数据使用授权协议


【五、认证机制 (auth.js)】

Token 存储方式：uni.setStorageSync / getStorageSync
    - 键名：X-TOKEN（Token）、USER_INFO（用户信息JSON）

工具函数：
    getToken()      获取Token
    setToken(token)  保存Token
    removeToken()    删除Token
    getUserInfo()    获取用户信息(自动JSON.parse)
    setUserInfo(info) 保存用户信息(自动JSON.stringify)
    isLoggedIn()     是否已登录(判断Token是否存在)
    logout()         退出登录(清除Token+用户信息)


【六、请求封装 (request.js)】

核心逻辑：
    1. 拼接 BASE_URL（当前为空，对接时填写后端地址）
    2. 检查URL是否在白名单（登录/注册/发短信 不需要Token）
    3. 非白名单请求自动在 header 中添加 X-TOKEN
    4. 返回 Promise
    5. 401状态码自动清除登录态并跳转登录页

白名单路径：
    /api/login
    /api/register
    /api/sms/send

便捷方法：
    request.get(url, data)
    request.post(url, data)

【九、对接后端要点】

需要对接的接口（约6-7个）：

    1. POST /api/login
       参数: { username, password }
       返回: { token, userInfo }

    2. POST /api/logout
       需Token

    3. GET /api/home
       首页数据(轮播图/待办/资讯)

    4. POST /api/enterprise/create
       提交企业信息表单
       需Token

    5. POST /api/enterprise/update
       修改企业信息
       需Token

    6. GET /api/report/list
       查询报告列表(含PDF下载URL)
       需Token

    7. GET /api/enterprise/status
       查询审核状态
       需Token

对接步骤：
    1. 在 request.js 中设置 BASE_URL
    2. 登录页：替换模拟登录为真实接口调用
    3. 我的页：onShow() 中请求审核状态和报告列表
    4. 企业录入：提交时调用 create 接口
    5. 首页：加载首页数据接口


【十、特别说明】

1. 所有 computed 属性中的碳排放计算都是前端实时计算的，
   不需要调后端接口。这样用户填数据时能实时看到计算结果。

2. 评分逻辑完全在前端实现（create-body.vue 的 scores 计算属性），
   但后端也应该有一份相同的评分逻辑做校验。

3. 行业选择弹窗使用的是自定义 mask + popup 组件，
   不是 uni-app 的 picker 组件。

4. 所有样式使用 scoped，不会互相影响。

5. 页面间传参方式：
   - Token/用户信息：通过 Storage (auth.js)
   - 企业数据：通过 App.globalData
   - 页面跳转参数：通过 URL query 参数

6. 没有使用任何第三方UI组件库，全部手写CSS。

7. 兼容性：使用 var 而非 let/const，使用 function 而非箭头函数，
   确保在低版本微信基础库上也能运行。
